# ページ構成
- **HOME**
	- お知らせや最新ゲームを掲載
- **ABOUT**
	- 作者プロフィール、サイト概要、SNSアカウントへのリンクで構成
- **GALLERY**
	- 公開したゲームの一覧ページ
	- 並び順・見せ方は「発見導線」で詳細化
- **CONTACT**
	- お問い合わせフォーム
	- EmailJSを利用して実装
# 発見導線
- **GALLERYページでのゲームの見せ方**
	- PCでは2列、スマホでは1列のカードレイアウト
	- カードの構成要素: ゲームタイトル、サムネイル画像、簡単な説明文
	- 並び順は新着順
	- ジャンルタグは現状なし
	- 各カードは、そのゲーム専用のプレイページ（個別URL）へのリンクになっている
	- SNS投稿のリンク先は、GALLERYを経由せず直接この個別プレイページとする
	- 全ページ共通のヘッダーを実装し、どのページ（個別プレイページ含む）からも迷わず移動できるようにする
		- ロゴ（トップ画面（HOME）へのリンク）
		- ハンバーガーボタン（ABOUT／GALLERY／CONTACTなど他ページへのナビゲーションを開く）
# ゲームの組み込み方
- **各ゲームはiframeを使わず、HTML/CSS/JSファイルとして直接プレイページに組み込む（シンプル・ミニマムな構成を優先）**
	- ゲーム画面はPhaser製で、canvas要素として描画される
	- ゲームのマークアップは専用のラッパー要素で囲み、CSSクラス名/idの衝突を避ける
	- JSはESモジュール（`<script type="module">`）で読み込み、モジュールスコープによってサイト本体のスクリプトと自然に分離される
- **プレイページの構成**
	- 共通ヘッダー(ロゴ・ハンバーガーボタン) + ゲーム画面のcanvasのみ
- **canvasのレスポンシブ対応**
	- PhaserのScale Manager（`scale`設定）を利用する。基本はFITモード（アスペクト比を保ったまま親要素に収まるよう拡縮）を採用し、内部解像度の再計算やdevicePixelRatio対応はPhaser側に任せる
- **メタデータ管理**
	- GALLERYカード・プレイページのタイトル/サムネイル/説明文はHTMLに直書きする（公開本数が少ない想定のため、別データファイルは用意しない）
# 世界観・ビジュアルの統一
- **統一する範囲**
	- 各ゲームのアート・世界観はジャンル(RPG/経営シミュレーション/パズルなど)ごとに自由とし、ここでは統一しない
	- 統一するのはサイトUI/ブランド層のみ(ヘッダー・GALLERYカードなど、ゲーム本編のcanvas外)
	- ターゲットユーザーが求める「広告に煩わされない落ち着いた環境」を優先し、ミニマル・余白重視のトーンとする
- **サイト名・ロゴ**
	- 「スタジオささめ」を正式なサイト名として採用する
	- ロゴは当面テキストロゴ(文字組みのみ)とし、画像ロゴ化は必要になった時点で検討する
- **カラーパレット**
	- 藍・青系を基調色相としたブランドカラーで構成する
	- ベースは白/オフホワイト背景、キーカラー(見出し・リンク・ボタンなど)に藍色を使用する
	- 本文テキストは純黒を避け、濃いグレーでコントラストを保ちつつ硬さを抑える
	- 具体的な色コード(明度・彩度のバリエーション)はプロトタイプ作成時に確定する
- **タイポグラフィ**
	- Webフォントを導入し、環境差なく見た目を統一する(日本語はNoto Sans JP相当のゴシック体を軸とする)
	- 見出し・本文はウェイト差で階層を表現し、装飾的な書体は使わない
- **GALLERYカードの見た目統一**
	- ジャンルの異なるサムネイル画像が並んでも雑然と見えないよう、カード側で共通ルールを持たせる
	- サムネイルは共通のアスペクト比・トリミングルールで表示する(画像のはみ出しはクロップして揃える)
	- カードの余白・角丸・枠線/影のスタイルを共通化し、画像の個性が出てもカード自体は揃って見えるようにする
	- タイトル・説明文のタイポグラフィ・表示行数上限もカード間で統一する
